A general-purpose AI agent you own.

Give woyo a goal, not a procedure. It understands the task, makes a plan, picks the right tools, acts, observes what happened, adapts when things break — and reports back with verified sources and honest uncertainty. Human approval is built in wherever actions have consequences.

Talk to your agent — from a phone

The same plan → act → verify core, now behind two frontends that need no computer on your side: a Telegram bot and a passcode-protected web chat. Conversations persist across restarts; every message gets its own budget; research answers still arrive with citation-checked sources. And since v0.6 it's a file channel: send documents, PDFs, archives, photos (it can view them) or voice notes — and ask for files back, delivered right in the chat.

📱 Telegram bot

Long-polling over plain HTTP — zero extra dependencies. /new resets the conversation, /status shows usage. One chat at a time, typing indicator while it works.

🌐 Web chat

Stdlib server + one embedded page. Passcode-gated and rate-limited, so it is safe to expose publicly — the model key never reaches the browser.

🚀 Free 24/7 hosting included

The Telegram bot runs on GitHub Actions (public repos: unlimited minutes) with conversation state synced to a private repo — deploy/gha-telegram/. Secrets live in repo settings, never in the repo.

principles

Not a chatbot with an agent-themed UI

Most "AI agents" autocomplete a conversation. woyo is a from-scratch agent runtime designed around the things that actually make agents trustworthy.

⟳Real loop, not a script

Plan → act → observe → adapt → verify, backed by a genuine state machine with budget enforcement — step, time, token, cost and tool-call limits, plus loop detection. It can never spin forever.

🧩Tools are plugins

A standardized Tool protocol: typed arguments, permissions, timeouts. Register a new tool in ~20 lines and the agent discovers it. No core changes.

🔌No vendor lock-in

13 model providers behind one interface — swap the planner, executor and summarizer independently per role. Local Ollama works offline; free tiers keep the bill at $0.

🛡️Security is structural

External content is wrapped as untrusted data, never instructions. SSRF-hardened fetching. Approval gates on consequential actions — denied by default when no human is reachable.

📡Observable by design

Every run emits structured events — tool calls, durations, token usage, cost estimates. The CLI live view, the future web UI and the eval harness all consume the same stream.

🛑Stops when it should

Budgets yield honest partial results, not fabricated ones. When woyo couldn't verify its own work, it says so: verified: false, with open questions listed.

the core loop

Understand → Plan → Act → Verify

Every task runs the same supervised loop. Failures produce typed observations the agent reasons about; success requires checking its own work before reporting.

Understand→ Plan→ Act (tools)→ Observe→ Evaluate→ Verify→ Report + sources

↺ replan: errors and surprises feed back into the next iteration — with per-task budgets enforced on every single step of the way.

providers

Bring any model — or three

A thin provider abstraction routes each role (planner / executor / summarizer) to a different model. Cheap models for routine steps, strong models for hard reasoning. All live-verified in September 2026.

roadmap

Eight phases, honest exit criteria

A phase is done when its criteria pass — not when its code exists. Full details in docs/ROADMAP.md.

Agent core (MVP)

Loop, planner, tool system, model routing, budgets, injection defenses, CLI, test suite.

done · v0.1
Phase 2
Research depth

Response caching, bounded crawling, citation verification against observed URLs, cross-check prompts, search budgets.

done · v0.2
v0.3
Chat frontends

Telegram bot + mobile web chat, transcript memory that survives restarts, per-message budgets, free HF Space hosting recipe.

done · v0.3
v0.4
Persistence, tasks & memory

Resumable task queue — the loop checkpoints every step, so a SIGKILL loses nothing. Long-term memory with offline-first embeddings, fully auditable: list, search, delete.

done · v0.4
v0.5
Execution, sub-agents & pressable approvals

python_exec with scrubbed env + persistent workspace, approval-gated shell, workspace file tools, spawn_agent sub-agents (depth-1, one budget), Telegram inline Approve/Deny buttons.

done · v0.5
v0.6
Files in, files out

Send the bot documents, PDFs, archives, photos (vision via free models, honest fallback) and voice notes — extracted as untrusted data, persisted across rotations. Ask it to create files: send_file delivers them right in the chat.

done · v0.6
v0.7
Documents that render, requests that can't be lost

create_document turns markdown into polished PDFs with bundled Arabic/RTL-aware typography — no more black squares. The chat states it has no background execution and injects recorded facts about the last turn, so "did you finish?" is answered from ground truth. Updates are journaled before processing and drained on the next boot; the bot self-rotates and dispatches its own successor.

done · v0.7
v0.8
Self-aware, proactive, and keeps its promises

Every prompt carries the ground truth of where the agent runs — its @username, the current chat_id, the chats it is in, its complete real tool list, and an honest cannot-list — so "I can't reach Telegram" is structurally gone. Four Telegram tools reach any known chat (allowlisted, approval-gated). And "I'll do it later" became schedule_task: a row in the database that runs at its time and reports back — verified live end-to-end.

done · v0.8

quickstart

Running in two minutes

Python 3.11+. One model key of your choice — free tiers work. Search works keylessly out of the box via DuckDuckGo.

# clone & install git clone https://github.com/bessghiermohamed/woyo cd woyo python -m venv .venv && source .venv/bin/activate pip install -e ".[dev,search,extract]" cp .env.example .env # add ONE model key woyo doctor # verify your setup
# give it a goal — not a procedure woyo run "Compare the three most recent Python releases and their headline changes. Cite sources." # interactive mode woyo chat
